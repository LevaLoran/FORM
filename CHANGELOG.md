## Бета 0.18 — совместные задания (локализация), уведомления, дерево навыков

### Уведомления и напоминания
- Новый модуль `notifications.js`: объяснение перед запросом разрешения, системные Web Notifications только после согласия.
- Внутриприложенческие уведомления (тосты + очередь) и интеграция с напоминаниями.

### Дерево навыков
- 4 ступени вместо 3 в каждой ветке (пороги 0 / 15 / 35 / 65 очков направления).

- Усиленные кросс-зависимости с соседними ветками на верхних ступенях.
- Новые названия вершин: Мудрец, Стойкость, Визионер (как ремесло/мастерство), Легенда тела, Создатель, Вдохновитель.

## Beta 0.07 — вход, облако для фото, анимации
- **Обязательный вход** через Google и GitHub (Supabase Auth, PKCE). Без подтверждённой сессии интерфейс приложения не показывается и не запускается; при каждом старте сессия проверяется на сервере (`getUser`), при недоступной сети используется сохранённая. Выход — в Профиле и Настройках.
- **Данные по аккаунтам:** первый вошедший на устройстве получает прежний локальный прогресс (ключи `lifeProtocol`/`lifeProtocolDB` не менялись), другие аккаунты на том же устройстве — свои отдельные хранилища.
- **Фото без лимита 8 МБ:** ни в интерфейсе, ни в коде размера нет. Оригинал уходит в приватный бакет `photos` по протоколу TUS (куски по 6 МБ, продолжение с места обрыва), с прогрессом, скоростью, отменой и повтором. Аватар (256 px) по-прежнему хранится локально; HEIC и другие форматы, которые браузер не читает, загружаются как оригинал без обрезки. Предыдущий оригинал заменяется, хранилище не растёт.
- Новые анимации: экран входа, скелетоны при запуске, рябь на кнопках, всплески при награде и новом ранге, плавные списки и модальные окна. Всё отключается при Reduce Motion.
- Кэш сервис-воркера `form-b010`.

### Настройка входа и облака (один раз)
1. Создайте проект на supabase.com.
2. **Authentication → Providers:** включите Google и GitHub. Client ID и Client Secret вставляйте только сюда (это секреты, в код и репозиторий они не попадают). В настройках OAuth-приложений Google и GitHub укажите callback `https://<project-ref>.supabase.co/auth/v1/callback`.
3. **Authentication → URL Configuration:** Site URL = адрес вашего сайта на GitHub Pages; в Redirect URLs добавьте тот же адрес (и `http://localhost:8000/` для разработки).
4. **SQL Editor:** выполните `supabase/setup.sql` (приватный бакет, доступ только владельцу, защита от переполнения: 2 ГБ на пользователя).
5. **Лимит размера файла:** задаётся только проектом. На бесплатном тарифе Supabase это 50 МБ на файл; чтобы принимать больше, перейдите на платный тариф и поднимите *Storage → Settings → Upload file size limit*. Приложение лимитов не добавляет.
6. **GitHub → Settings → Secrets and variables → Actions → Variables:** добавьте `SUPABASE_URL` и `SUPABASE_ANON_KEY` (публичный anon/publishable ключ). Workflow при деплое сам запишет их в `config.js`. Для локального запуска впишите те же значения в `config.js`.

Секреты (`client secret`, `service_role`) в клиентский код и в переменные репозитория не кладутся. Защита данных в облаке держится на политиках RLS из `setup.sql`; сама страница статическая, поэтому «закрыт» от гостей интерфейс, а не файлы сайта.

## Beta 0.09 — вход по почте и паролю, подключение только у владельца
- **Google убран.** Способы входа: GitHub и почта с паролем (регистрация, вход, «Забыли пароль?», смена пароля в Профиле). Ошибки показываются по-русски.
- **Формы «Подключить Supabase» больше нет.** Подключение к проекту задаёт только владелец: переменные репозитория `SUPABASE_URL` и `SUPABASE_ANON_KEY` (GitHub → Settings → Secrets and variables → Actions → Variables) или значения в `config.js` (там уже указан URL проекта, нужно добавить только publishable ключ). Значения из переменных имеют приоритет; пустые переменные ничего не затирают. Настройки, ранее сохранённые формой в браузере, удаляются и игнорируются.
- Кэш сервис-воркера `form-b012`.

### Настройка почты в Supabase
1. Authentication → Sign In / Providers → Email: включено (по умолчанию). *Confirm email* — рекомендуется оставить включённым.
2. **Важно про письма.** Встроенная почта Supabase предназначена для тестов: она шлёт письма только участникам вашей команды и не больше нескольких в час. Для обычных пользователей настройте свой SMTP: Authentication → Emails → SMTP Settings (подойдут Brevo, Resend и другие). Без этого регистрация и сброс пароля у посторонних людей работать не будут. Альтернатива: выключить *Confirm email*, тогда регистрация работает без писем, но «Забыли пароль?» всё равно требует почту.
3. Authentication → URL Configuration: Site URL и Redirect URLs = адрес сайта (нужны для писем со ссылками).
4. Хотите закрыть приложение для посторонних: Authentication → Sign In / Providers → отключите *Allow new users to sign up*, а нужных людей добавляйте вручную (Authentication → Users → Add user).

### Что даёт защиту, а что нет
Сайт статический: весь код работает в браузере, поэтому экран входа сам по себе не защита (его можно обойти правкой кода у себя в браузере). Реальную защиту дают настройки Supabase: политики RLS для хранилища (`supabase/setup.sql`), закрытая регистрация и то, что секретные ключи нигде не публикуются. Прогресс хранится локально в браузере пользователя и сервером не защищается.

## Beta 0.10 — синхронизация между устройствами, письма, аудит
**Что нового**
- **Единый аккаунт = единые данные.** Прогресс, задания, навыки и награды, отчёты, настройки (позывной), тема Dark/Light и аватар хранятся в облаке (`public.user_data`, RLS: только владелец). Новое устройство после входа получает всё автоматически.
- **Автосохранение и офлайн.** Изменения пишутся на устройство сразу и уходят в облако через ~1 с; без сети копятся локально (переживают перезагрузку) и отправляются при появлении связи. Другие устройства подхватывают изменения мгновенно (Realtime) или не позже чем через 45 секунд / при возврате на вкладку. Индикатор: точка в шапке и строка в Профиле → «Аккаунт».
- **Защита от конфликтов.** Запись идёт по номеру версии (`rev`): если другое устройство записало раньше, данные не перезаписываются, а сливаются трёхсторонним слиянием (база · устройство · облако): задания и выполнения объединяются без дублей, опыт и навыки считаются по уникальным выполненным заданиям, выполнение побеждает отмену, удаление с одного устройства не воскрешает задачи.
- **Первый вход на устройстве с уже существующим прогрессом:** вместо тихой перезаписи показывается выбор «Объединить / Взять из облака / Оставить с устройства». Выбранный вариант не удаляет ничего безвозвратно: прежняя версия остаётся в резервных копиях (а при выборе «из облака» локальная копия сохраняется на устройстве).
- **Серверные резервные копии:** триггер сохраняет предыдущую версию перед изменением (не чаще раза в 30 мин, 30 последних). В Профиле → «Копии» любую версию можно вернуть. Удалить прогресс запросом из браузера нельзя (политики DELETE нет).
- **Выход из аккаунта** сначала отправляет последние изменения; локальные данные не стираются.
- **Письма подтверждения:** ошибки отправки больше не маскируются под успех (честное «Не удалось отправить письмо»), есть повторная отправка (с паузой 60 с), понятные сообщения «письмо отправлено», «ссылка устарела», «почта подтверждена» и подсказка, если ссылка открыта в другом браузере.

**Обязательная настройка сервера (вручную)**
1. Supabase → SQL Editor → выполните весь `supabase/setup.sql` ещё раз (часть 2 добавляет таблицы синхронизации; скрипт безопасно запускать повторно).
2. Письма (без этого подтверждение почты у других людей не работает, это причина жалобы «письма не приходят»): встроенная почта Supabase отправляет только участникам вашей команды и не больше нескольких писем в час. Authentication → Emails → SMTP Settings → включите Custom SMTP (Brevo, Resend, Postmark и т.п.):
   - Sender email — адрес на **вашем домене**, который вы подтвердили у почтового сервиса (SPF и DKIM настроены у регистратора домена, иначе письма уходят в «Спам» или отклоняются);
   - Host / Port / Username / Password — из кабинета почтового сервиса (для Brevo и Resend это SMTP-ключ, не API-ключ);
   - после сохранения увеличьте лимит писем: Authentication → Rate Limits.
3. Authentication → URL Configuration: Site URL и Redirect URLs = `https://levaloran.github.io/FORM/`. Authentication → Emails → Templates: в шаблоне «Confirm signup» должна быть ссылка `{{ .ConfirmationURL }}`. Срок действия ссылки задаётся в Authentication → Sign In / Providers → Email (OTP Expiration, по умолчанию 1 час).
4. Если письма не приходят: Supabase → Logs → Auth покажет причину (ошибка SMTP, лимит, неподтверждённый домен). Пока SMTP не настроен, можно отключить «Confirm email» (тогда регистрация проходит без писем, но «Забыли пароль?» всё равно требует почту).
5. Ключ в `config.js`: если сайт публикуется «из ветки» (Settings → Pages → Deploy from a branch), workflow `pages.yml` не запускается, поэтому publishable-ключ должен быть вписан в `config.js` прямо в репозитории.

**Аудит: найдено и исправлено**
- Тема хранилась только на устройстве → теперь входит в синхронизируемые данные.
- Ошибка отправки письма могла выглядеть как успех → исправлено, добавлена повторная отправка.
- Ссылка подтверждения, открытая в другом браузере, не давала понятного результата → добавлено объяснение.
- Выход из аккаунта мог потерять последние изменения → перед выходом выполняется отправка.

**Известные ограничения**
- Сайт статический: интерфейс входа не заменяет серверную защиту; защиту данных обеспечивают политики RLS.
- При одновременной правке *одной и той же* задачи на двух устройствах побеждает правка того устройства, которое синхронизируется последним (выполнение задачи при этом не теряется).
- Импорт старой резервной копии объединяется с облаком, а не заменяет его: опыт не уменьшается. Чтобы откатить прогресс, используйте «Копии» в Профиле.
- Письма, SMTP и OAuth GitHub настраиваются вручную в панелях сервисов (см. выше): из кода это сделать нельзя.

**Как устроены переводы**
- Исходный язык — русский: ключ словаря — русская строка. Файлы: `i18n.js` (движок, выбор языка), `lang-data.js` (словари), `settings.js` (экран настроек). Цепочка запасных вариантов: язык → English → русский.
- Чтобы добавить язык: добавьте строку в `LANGS` в `i18n.js` и словарь в `lang-data.js` (`window.FORM_I18N.xx = {...}`).
- Пользовательские данные (названия задач, имя) не переводятся. Отчёты и сообщения создаются на языке, выбранном в момент создания.

## Beta 0.12 — отмена выполнения и звук победы
**Что нового**
- **Отмена выполненной задачи.** Нажмите на отмеченный кружок ещё раз: задача снова станет невыполненной, вернутся XP, очко навыка и запись в истории за сегодня; ранг пересчитывается. Полученные награды остаются у вас (отмена их не забирает). Отмену можно делать и после перезапуска приложения в тот же день.

## Beta 0.13 — сброс XP за период
**Что нового**

## Бета 0.14 — социальная система
- **FORM ID** (`FORM#483921`): создаётся автоматически при регистрации (триггер на `auth.users`) и для уже существующих аккаунтов, не меняется (защищён триггером), уникален. Копирование в один тап и ссылка на профиль.
- **Раздел «Друзья»:** Все друзья, В сети, Ожидание, Добавить друга; поиск по ID, @имени и имени; заявки (отправить, принять, отклонить, отменить), удаление из друзей без уведомления; встречная заявка принимается сразу.
- **Профиль:** отображаемое имя (общее с именем в приложении), @имя пользователя (раз в 7 дней, зарезервированные имена закрыты), о себе, статус, ссылки (только http/https), аватар с рамкой, баннер (цвет или своё изображение), цвет, декор, фон, закреплённые достижения, дата регистрации.
- **Публичный профиль** и предпросмотр «как видят другие» (для любого пользователя и для друга) считаются на сервере тем же кодом, что и чужой просмотр.
- **Приватность:** заявки, онлайн-статус, последняя активность, доступ к профилю, поиск по имени, скрытие элементов, блокировки. Заблокировавший для заблокированного «не существует».
- **Уведомления:** новая и принятая заявка, системные; бейджи на колоколе, в меню и во вкладке «Ожидание».
- Онлайн-статус: приложение отмечается раз в минуту, «в сети» держится 2 минуты. Список обновляется по realtime, при его отсутствии каждые 30 секунд.
- Безопасность: клиенты не пишут в социальные таблицы напрямую, всё идёт через функции `security definer` с проверкой входа; чужие профили читаются только через них; вспомогательные функции закрыты от клиентов; картинки принимаются только как data-URL jpeg/png/webp ограниченного размера.
- `setup.sql` дополнен частью 3 (запустить повторно). Кэш сервис-воркера `form-b017`.

## Бета 0.15 — приватность, теги и права владельца
- **Приватность:** найдена и закрыта утечка: стартовое @имя строилось из части адреса почты до «@» и было публично видно. Теперь оно берётся только из логина GitHub либо `user` + 6 цифр. Старые имена, созданные из почты (и не менявшиеся вручную), при запуске `setup.sql` заменяются, владельцу приходит системное уведомление. Почта, личные данные и данные аккаунта не возвращаются ни одной публичной функцией и недоступны даже владельцу в Owner Panel.
- **Роли:** `profiles.role` (`user`, `tester`, `owner`). Менять роль можно только функциям Owner Panel: триггер блокирует любое другое изменение. `FORM#401167` — Owner, тег «I'm Ceo Bitch»; `FORM#107445` — Tester, тег «Тестировщик» (назначаются по FORM ID существующим аккаунтам, дублей не создаётся).
- **Теги:** отдельная таблица, запись только через функции владельца. Видны рядом с именем в профилях и списках. Имя и статус нельзя сделать равными чужому тегу.
- **Права владельца:** все рамки (в том числе эксклюзивные `aurora`, `crown`, `void`) и все достижения открыты автоматически и проверяются на сервере. Закрытая рамка у обычного пользователя не показывается и не сохраняется.
- **Owner Panel:** пользователи, роли, теги, выдача эксклюзивных рамок, журнал действий (`admin_log`). Кнопка видна только владельцу, прямой переход без прав возвращает на главную, а каждая функция `admin_*` сама проверяет роль.
- Кэш сервис-воркера `form-b018`. `setup.sql` дополнен частью 4: запустить повторно.

## Бета 0.16 — редизайн интерфейса
- **Навигация:** четыре основных раздела в нижней панели (Главная, Статистика, Друзья, Профиль), второстепенные разделы и управление сверху (чипы, уведомления, тема, настройки). Верхняя строка шапки на телефоне убирается при прокрутке. На компьютере нижняя панель превращается в боковую.
